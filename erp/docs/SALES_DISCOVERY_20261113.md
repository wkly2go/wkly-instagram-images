# 영업 발굴·나라장터 통합 후속 변경 — 2026-11-13

## 목적과 범위

조사한 민간 브랜드·행사와 공공 공고를 검토하고 기존 영업·수주 기록으로 이어지게 한다. 기존 관리 기능, 저장 데이터, 권한·버전 충돌 검사를 사용한다. 이번 변경은 외부 조사를 자동 실행하는 서비스나 입찰 대행 기능이 아니다.

## 화면 동선

- `/sales`: **수주 파이프라인 / 민간 영업 후보 / 나라장터 공고**. 민간·공고 탭은 기존 연락처 검토함·나라장터 자료와 같은 저장소를 사용한다. 기존 `/leads`, `/tenders`도 유지한다.
- 수주 파이프라인의 **유입 경로 필터**에 나라장터를 포함한다. 회사·단계·검색·후속 연락 조건과 함께 페이지 나누기 전에 필터링한다.
- 상세 ID 또는 신규 작성 URL은 영업 편집기를 표시한다. 업무 탭 이동은 기존 미저장·처리 중 이동 보호를 따른다.
- 나라장터 공식 조회의 분야 버튼은 SNS 홍보·콘텐츠 제작·행사 운영·전시·공간 검색어를 채운다. 별도의 조회 버튼을 눌러야 API 요청한다. 제목 검색으로 모든 관련 공고를 포괄한다고 주장하지 않는다.

## 조사 결과 가져오기

민간·공고 탭의 **발굴 보고서 가져오기 → 발굴 후보 미리보기 → 후보 체크 → 선택한 후보 검토함에 저장** 순서다. 선택한 후보를 기존 검토함에 `검토` 상태로 명시적으로 저장한다. 한 건을 먼저 수정할 때는 **이 후보 검토해 등록 → 기존 편집기 → 저장** 경로도 유지한다. JSON 파일 선택(최대 1MB) 또는 붙여넣기를 지원한다. 단일 객체 또는 최대 20개 배열, 150,000자 이하이며 각 행 오류를 표시한다. 파일을 읽는 동안 입력·닫기·탭 이동을 막는다.

공통 필수 항목은 `kind`, `title`, `target`, `source_url`, `verified_on`, `evidence`, `need`, `offer`, `next_action`이다. 출처·확인일·수요·제안·다음 행동과 기존 접촉 여부를 메모에 보존한다. 확인일과 근거는 작성자의 진술이며 프로그램의 사실 인증이 아니다.

- `contact`: 이메일 또는 인스타 계정명이 필요하다. 기존 접촉 여부는 미확인으로 둘 수 있다. 관리 상태를 확인한 뒤 영업에 연결한다.
- `tender`: 공고번호와 차수가 필요하다. 참가 조건은 보고서 내용과 관계없이 **추가 확인**으로 시작한다. 공고 금액은 계약액이나 우리 매출로 취급하지 않는다.
- `deadline`에는 시간대가 포함된 가장 이른 필수 마감을, `deadlines`에는 서류·가격·등록·질의 등 서로 다른 마감과 제출 방식을 적는다. 상세 마감은 메모에 보존한다. 메모는 조사 당시 스냅샷으로 명시한다. 편집기에서 마감·금액을 고친 경우 연결 전에 메모도 최신 원문과 대조한다.
- 선택 저장에서 성공한 후보는 제외하며 실패 후보 ID·초안·오류는 열린 창에서 유지한다. 같은 자료의 재미리보기에도 성공 항목을 다시 저장하지 않고 남은 ID를 유지한다. 자료 변경은 확인을 받으며 기존 저장 항목을 덮어쓰지 않는다. 원문·실패 상태는 새로고침 후 영구 보존되지 않는다.
- 단건 편집기로 넘기는 경로는 나머지 후보와 원문을 닫는다. 이미 저장 시도한 후보는 새 편집기로 이동시켜 다른 ID로 재생성하지 않는다. 원본 보고서는 별도로 보관한다.
- 기존 공고번호·차수 또는 연락처 중복은 기존 저장 경로의 검사에 따른다. 기존 자료를 덮어쓰지 않는다.
- 조사 결과의 다음 행동은 메모로 전달된다. 영업 연결 뒤 실제 다음 행동·연락일을 지정한다. 예약·알림이 자동 등록된다고 설명하지 않는다.

## 공공 영업 검토

공고 원문과 정정 여부, 업종·지역·실적·직접생산 요건, 수행 인력·원가를 확인한다. 검색 결과 요약만으로 적격을 판단하지 않는다. 서류 방문 제출과 전자 가격입찰이 다른 시각에 마감될 수 있다. 각 마감과 제출 방식을 구분해야 한다.

영업 연결은 **발굴** 단계의 기회 생성이다. 참가 자격 충족, 제출 완료, 우선협상·낙찰, 계약 체결을 자동 확정하지 않는다. 계약 확인 후 수주 단계와 프로젝트 연결을 기록한다.

이번에 별도로 조사한 실제 후보와 연락 정보는 공개 코드나 매뉴얼의 예시 데이터에 넣지 않는다. 운영 후보 저장 여부는 별도 결과로 보고한다.

## 배포·검증 기록 원칙

이 문서는 구현 동선과 한계를 기록한다. 이번 변경의 전체 테스트·빌드·운영 배포 결과는 최종 작업 보고에서 확인한다. 문서 작성만으로 테스트 또는 운영 배포가 완료됐다고 간주하지 않는다. 기존 매뉴얼 이미지 6개는 보존했고, 새 UI의 운영 계정·PC·모바일 캡처는 새로 만들지 않았다.

이번 변경에는 DB 마이그레이션이나 서버 함수 재배포가 없다. 0107·0113·0114·0115를 다시 실행하지 않는다. meeting-minutes·gmail·g2b-search 서버의 2026-11-13 배포 이력은 유지한다. 나라장터 서버 키·활용 승인·실제 운영 응답 검증은 별도다. 추가 유료 AI 호출·예산 변경·연락 발송·실제 광고 집행·게시·입찰은 하지 않는다.

## 영업 실행·배치 저장 후속 보완

### 선택한 발굴 후보 저장

`DiscoveryIntake`는 체크한 후보만 저장한다. 성공 후보는 제거하고 실패·불확실 후보는 동일 ID와 입력으로 다시 확인한다. 불확실 쓰기는 같은 ID·전체 정규화 내용·초기 저장 버전·연결 미설정 상태를 확인한 경우에만 저장 완료로 복구한다. 명시적인 중복·권한·DB 거절은 성공으로 바꾸지 않는다. 재시도는 선택한 남은 후보에 한정하며 자동 반복하지 않는다.

현재 열려 있는 가져오기 창의 원문과 실패 상태만 보존한다. 새로고침 후 복구·영구 임시 보관 기능은 아니다. 검토함에 저장해도 `확인` 상태로 승격하거나 영업에 자동 연결하지 않는다.

### 영업 단계별 실행

`SalesPlaybook`은 콘텐츠·광고, 공간·인테리어, 나라장터·공공 입찰의 3개 업무에 8개 기존 단계별 목표·담당자 할 일·다음 단계 확인 근거·다음 행동 예시를 제공한다. 유입 경로가 나라장터이면 공공 안내를 우선하고, 나머지는 수행 회사로 콘텐츠/공간 안내를 선택한다.

**다음 행동 예시 적용**은 `next_action`만 수정한다. 기존 내용과 다르면 교체를 확인한다. 단계·연락일·금액·계약 상태는 자동 변경하지 않으며, 변경한 초안을 명시적으로 저장해야 한다. 체크리스트는 확인할 항목이며 완료 상태·수주 확률 판정이 아니다.

### 활동 조회·불확실 저장

영업 상세와 활동 목록 조회를 분리하여 활동 조회 실패가 영업 상세 수정까지 막지 않는다. 활동 저장이 불확실하면 원래 ID·내용·작성자를 보존하고 입력을 잠근다. **저장 상태 확인**은 같은 요청을 조회하고, **동일 내용으로 재시도**는 원래 요청을 사용한다. 창을 닫거나 새로고침한 뒤에는 요청 정보가 남지 않으므로 이력을 확인한 후 재입력해야 한다.

### 수주 인계와 연결 복구

수주 편집기에서 **새 프로젝트 만들기**는 별도 창의 기존 프로젝트 등록 화면을 연다. 이 링크가 프로젝트를 생성하거나 영업 내용을 자동 이관하지 않는다. 등록 뒤 **프로젝트 목록 새로고침 → 같은 회사·거래처 프로젝트 선택 → 저장**한다. 회사·거래처 불일치 또는 존재를 확인하지 못한 선택은 오류를 표시한다. 영업 입력 내용은 원래 창에서 유지한다.

후보의 영업 연결 성공 응답 뒤 후보 상세 재조회에 실패하면 확인된 영업 링크를 유지한다. 최신 후보 자료를 다시 확인하기 전에는 편집·저장을 잠가 오래된 버전으로 덮어쓰지 않게 한다.
