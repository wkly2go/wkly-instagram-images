# 카카오톡 채널 챗봇 검토 (로드맵 1-4)

작성 2026-11-17 · 읽는 사람: 대표, 다음 개발 담당 · 일정표 `erp/docs/ROADMAP.md` 1-4

## 읽기 전에

- 이 문서는 조사 3건(카카오 정책 · 메시지를 받는 방법 · 인트라넷 코드)의 결과만으로 썼습니다. 모르는 것은 추측하지 않고 '확인 못 함'으로 적었습니다.
- **카카오 페이지는 한 곳도 직접 열지 못했습니다.** 작업 환경이 허용된 주소만 열리는 방식이라 카카오 주소가 막혀 있습니다(조사할 때와 이 문서를 쓸 때 두 번 확인 · 8장). 그래서 카카오에 관한 내용은 모두 무료 내장 검색이 보여 준 **그 페이지의 발췌**가 근거입니다. 유료 검색 도구는 쓰지 않았습니다.
- 인트라넷 코드에 관한 내용은 저장소 파일을 직접 읽어 확인했습니다. 운영 DB 는 조회하지 않았습니다.
- 괄호 안 기호(A6 · B16 …)는 8장의 출처 번호입니다. A~F 는 공식 페이지 발췌, G 는 카카오 개발자 포럼(데브톡) 글, H 는 카카오가 아닌 회사의 자료, R 은 저장소 파일입니다.
- 가격과 정책은 바뀝니다. 대부분의 페이지에서 날짜를 확인하지 못했습니다. 결정 전에 카카오 화면에서 다시 봐야 합니다.

낱말
- **채널**: 회사 이름으로 여는 카카오톡 공식 계정. 고객이 여기로 채팅을 겁니다.
- **비즈니스 채널**: 사업자 서류 심사를 받은 채널.
- **파트너센터**: 채널을 관리하는 카카오 화면. 2025-12-08 에 예전 '채널 관리자센터'가 여기로 합쳐졌습니다(E5). 예전 안내와 메뉴 이름이 다를 수 있습니다.
- **챗봇 관리자센터**: 챗봇을 만드는 카카오 화면(chatbot.kakao.com). 예전 이름은 '카카오 i 오픈빌더'입니다(B6 · G1).
- **블록**: 챗봇 대화의 한 칸. '웰컴 블록'은 첫 인사, '폴백 블록'은 봇이 못 알아들은 말에 답하는 칸입니다(B11 · C7).
- **스킬**: 챗봇이 고객의 말을 받았을 때 우리 서버를 불러 답을 받아 가는 연결.
- **콜백**: 5초 안에 답하지 못할 때, 조금 뒤에 답을 따로 보내는 방식.
- **Event API**: 챗봇이 고객에게 먼저 말을 거는 기능(유료).
- **딜러사**: 카카오와 계약하고 알림톡 · 상담톡 같은 유료 메시지 상품을 파는 회사.

## 1. 결론

만들 수 있고, '무료 서비스만' 원칙 안에서 됩니다. 다만 무료인 범위가 좁습니다. **고객이 회사 채널에 먼저 말을 걸면 → 챗봇이 5초 안에 정해 둔 문구로 답하고 → 그 내용을 인트라넷이 받아 저장하는 것**까지입니다(챗봇의 채팅 서비스에는 요금이 없다고 안내되어 있습니다 · A6 · E1). **우리가 먼저 보내거나 나중에 카카오톡으로 답을 보내는 수단은 모두 건당 요금이 붙습니다**(Event API 15원 · 채널 메시지 15~20원 · 알림톡 · 브랜드 메시지 · 상담톡). 그래서 챗봇은 '신규 문의 접수 창구'로만 쓰고, 접수된 문의는 이미 있는 웹 문의함 · 영업 대상 자동 등록 · 알림으로 넘기며, 답은 지금처럼 대표 승인을 거친 메일이나 사람이 직접(전화 · 채널 1:1 채팅) 하는 구성을 권합니다. 개발은 4~5일 분량입니다. 지금 바로 개발부터 시작하기보다, 돈과 개발이 들지 않는 준비(회사 채널 확인 · 비즈니스 채널 신청 · 챗봇 관리자센터 가입)와 '메시지가 실제로 우리 서버까지 오는지' 시험을 먼저 하기를 권합니다. 카카오에 로그인해야만 알 수 있는 조건이 남아 있고(6장), 2단계 일정(11/19 시작)과 겹치기 때문입니다.

대표께서 정해 주실 것
1. **개발 시점** — 2단계(외부 협업방) 앞, 2단계와 3단계 사이, 로드맵이 끝난 뒤 가운데 하나(7장).
2. **챗봇 고정 문구 승인** — 인사 · 개인정보 안내 · 접수 완료 문구. 자동으로 나가지만 고객에게 가는 글입니다.
3. **AI 가 자유롭게 답하는 기능** — 이번에는 넣지 않기를 권합니다. 승인 없는 자동 응답이 되고, AI 비용이 들고, 카카오 쪽 조건을 확인하지 못했습니다.

로드맵의 사전 검토(11/05 · R1)에서 고쳐 읽을 곳
- '카카오 i 오픈빌더' → 지금 이름은 '챗봇 관리자센터'입니다. 이름이 바뀐 때는 확인 못 함.
- '거래처가 회사 채널에 보낸 메시지만 받아 올 수 있음' → 더 정확히는 **챗봇이 응답 중인 메시지만**입니다. 사람 상담으로 넘어간 뒤의 대화는 오지 않습니다.
- '채널 개설 · 심사 필요' → 채널 개설에는 심사가 없습니다. 심사는 비즈니스 채널 인증에 있습니다. 챗봇을 만들기 전에 따로 심사가 있는지는 확인 못 함(6장).
- '알림톡은 유료라 보류' → 그대로입니다. 먼저 보내는 다른 수단도 모두 유료입니다.

## 3. 인트라넷에 붙이는 방법

아래 이름(`sales-kakao` 등)과 구성은 제안입니다. 만들기 전에 3-4의 확인부터 합니다.

### 3-1. 받는 흐름

```
고객 (카카오톡 채널 채팅방)
 └ 챗봇 블록: 인사 → 문의 접수(구분 · 브랜드 · 내용 · 연락처 · 개인정보 동의) → 그 밖의 말
     └ 스킬 (HTTP POST · JSON · 5초 안에 답)
         └ 인트라넷 새 함수: 확인 값 비교 → 크기 · 형식 확인 → DB 함수 1회
             ├ 수신 표에 저장 (같은 요청은 한 번만 · 수신 거부 / 삭제 요청 표시)
             ├ 웹 문의함에 '문의'로 등록 (유입 kakaotalk)
             └ 관리자 알림 (금액 없음)
         └ 정해 둔 문구로 접수 확인 응답
인트라넷: 웹 문의함 '바로 응대' → 영업 대상 자동 등록(10분마다) → 대표 승인 뒤 메일 · 전화 · 사람의 1:1 채팅
```

1. 고객이 회사 채널 채팅방에서 말을 겁니다. 처음 들어온 사람에게는 웰컴 블록이 인사를 한 번 보냅니다(B11).
2. '문의 접수' 블록이 질문을 차례로 던져 답을 받습니다(되묻기 · C2). 받을 것은 구분(더위클리 · 아트리어) · 회사나 브랜드 · 문의 내용 · 연락처(메일 또는 전화) · 개인정보 수집 동의입니다. 전화번호 형식은 카카오가 알아봅니다(C3). 메일 전용 형식은 확인하지 못해, 글자 그대로 받아 우리 쪽에서 형식을 검사합니다.
3. 답이 모이면 블록에 연결한 스킬이 인트라넷 주소로 요청을 보냅니다(HTTP POST · JSON · B16 · B20 · C4). 요청에는 고객의 말, 블록 정보, 고객을 구분하는 값이 들어 있습니다. 이름 · 전화번호는 들어 있지 않습니다(B17).
4. 인트라넷의 새 서버 함수가 ① 요청 머리에 실린 확인 값을 금고의 값과 비교하고 ② 본문 크기와 형식을 확인하고 ③ DB 함수를 한 번 부릅니다. AI 는 부르지 않습니다.
5. DB 함수가 한 번에 처리합니다. 수신 표에 저장(같은 요청은 한 번만) · '수신 거부'나 '삭제 요청'이면 표시하고 관리자에게 알림 · 접수가 끝난 건은 웹 문의함에 '문의'로 등록 · 관리자 알림 한 줄.
6. 함수가 5초 안에 정해 둔 문구로 답합니다. 저장에 실패했으면 '접수했다'고 답하지 않습니다.
7. 그다음은 지금 있는 기능이 이어받습니다. 영업 › 웹 문의함 '바로 응대'에 뜨고, 10분마다 도는 단계가 영업 대상으로 올리고, 알림은 푸시와 대표 비서의 하루 정리에 나옵니다.
8. 답하기. 메일이 있으면 문의함 '답장 쓰기'(메일 창만 엽니다)나 영업 기획안 → 대표 승인 → 보내기 승인. 전화만 있으면 담당자가 전화합니다. 카카오톡으로 답하려면 고객이 '상담직원 연결' 버튼을 누른 뒤 사람이 파트너센터 1:1 채팅에서 직접 씁니다(A11 · A12).
9. 사람 상담으로 넘어간 뒤의 대화는 인트라넷으로 오지 않습니다(G7). 남겨야 하면 '대화 내보내기' 파일을 지금 있는 '카카오톡 대화 가져오기'로 프로젝트에 넣습니다. 그 파일 형식이 맞는지는 확인 못 함.

### 3-3. 새로 만들 것

1. 서버 함수 `supabase/functions/sales-kakao` (index · handler) + 배포 묶음 + 시험 2종.
2. 마이그레이션 1개: 수신 표(비공개 구역 · 서버만 접근) · 받기 / 현황 DB 함수 · 스킬 확인 값(시스템이 만들어 금고에 저장) · 전화만 있는 문의의 영업 대상 등록 보강 · 미응대 경보 단계 한 줄.
3. 화면: '영업 설정 · 점검'에 '카카오톡 채널 연결' 카드(스킬 주소 · 확인 값 복사 · 받은 건수), 웹 문의함에 '카카오톡' 표시와 전화 응대 안내, `api` · `supabaseApi` · `demoApi`.
4. 챗봇 관리자센터의 블록 구성(코드가 아니라 카카오 화면 작업).
5. 개인정보처리방침의 카카오톡 채널 항목 · 사용설명 · 로드맵 기록.

### 3-4. 만들 때 지킬 것 (개발 담당)

- **먼저 확인**: 표 `web_inquiries` 의 정의(필수 칸 · 제약 · 권한)가 저장소 마이그레이션에 없습니다(R6 · R7). 새 출처에서 행을 넣기 전에 DB 에서 확인합니다.
- **5초**: DB 함수 1회, AI 없음, 바깥 호출 없음으로 만듭니다. 처음 불릴 때의 지연이 5초에 걸리는지는 실제로 재 봐야 합니다(F7).
- **응답 형식**: JSON, version 은 '2.0'만. 말풍선 1~3개, 바로가기 버튼 10개 이하, 글 1,000자(500자를 넘으면 접힘), 응답 하나가 30,720 bytes 를 넘으면 고객에게 가지 않습니다(B17 · B13 · C5).
- **요청 확인**: 카카오 요청에 서명이 붙는다는 문서를 찾지 못했습니다. 문서가 안내하는 방법은 스킬 설정의 '헤더값 입력'에 넣은 값을 서버가 비교하는 것입니다(B16). 여기에 본문 크기 제한 · 형식 검증 · 사람별 횟수 제한을 더합니다. 요청의 봇 ID 가 우리 봇인지 보는 것은 보조 수단입니다(B9). 카카오 서버의 IP 목록은 확인 못 함(D6).
- **확인 값 · 주소를 바꾸면** 스킬을 다시 배포해야 반영됩니다(B16).
- **고객 구분 값**: 봇마다 다른 값(최대 70자)과 채널 기준 값이 옵니다(B17). 값이 비어 온다는 신고가 있어(G3) 첫 시험에서 실제 요청을 기록해 확인합니다.
- **저장**: 지난 챗봇 대화를 나중에 불러오는 방법을 확인하지 못했습니다. 받는 순간 저장합니다. 우리 서버가 잠깐 끊긴 동안의 말은 다시 받을 수 없다는 포럼 글이 있습니다(G15).
- **개인정보**: 주민등록번호 등은 받지 않게 안내하고 걸러 냅니다. 수신 표는 비공개 구역에 둡니다.
- **시험**: 콜백은 쓰지 않습니다. 봇테스트 → 시험 채널 → 실제 휴대폰 순서로 봅니다. 개발 중에는 운영 채널로 아무것도 내보내지 않습니다.

## 4. 대표 · 담당자가 카카오 화면에서 할 일

비밀 값(확인 값 · 키)은 대화 · 문서 · 메신저에 적지 않습니다. 인트라넷 화면에서 복사해 카카오 화면에 붙여 넣기만 합니다.

1. **회사 채널 확인.** 카카오비즈니스 파트너센터에 회사 카카오계정으로 들어가 회사 채널이 있는지 봅니다. 없으면 만듭니다(무료 · 바로 생성 · A1 · B1). 저장소에서는 회사 채널 주소를 찾지 못했습니다.
2. **비즈니스 채널 신청.** 채널 마스터만 할 수 있습니다. 심사는 영업일 3~5일, 다른 문서는 3~7일입니다(A3 · A4 · B2). 서류는 문서마다 설명이 다릅니다. 한 문서는 법인 대표면 사업자등록증 + 휴대폰 본인인증, 직원이면 사업자등록증 + 본인 명의 전자증명서라고 하고(B1), 다른 문서는 사업자등록증과 재직증명서 또는 대표자 신분증이라고 합니다(A3). 신청 화면의 안내를 따릅니다. 주민등록번호는 가리고 올립니다. 같은 사업자 · 같은 목적의 비즈니스 채널이 이미 있으면 더 만들 수 없습니다(B1).
   - 1차 기능에 비즈니스 인증이 꼭 필요한지는 확인하지 못했습니다. 다만 시험용 채널을 만들려면 필요하고 기다리는 시간이 있으니 먼저 신청합니다.
3. **챗봇 관리자센터 가입.** chatbot.kakao.com → 카카오비즈니스 가입 → 챗봇 관리자센터 회원 가입 → '봇 만들기' 버튼(B7). 예전 안내에는 챗봇을 만들기 전에 'OBT 심사'(최대 6일)를 받는다고 적혀 있고 지금 안내에는 그 말이 없습니다(A5 · B7). 가입할 때 심사 안내가 나오는지 확인해 이 문서 6장에 적습니다. 개발 담당의 카카오계정을 관리자로 추가합니다.
4. **지금 쓰는 기능 확인.** 채널에서 '채팅방 메뉴'(커스텀 메뉴 · 리스트 메뉴 · 자동응답 메시지)나 카나나 상담매니저를 쓰고 있다면 챗봇과 같이 쓸 수 없습니다(A9 · B3). 끌지 말지 먼저 정합니다.
5. **시험 채널 만들기.** 비즈니스 인증이 끝나면 '개발자용 채널 만들기'로 시험 채널을 만듭니다(A10 · B24). 기존 채널 친구에게는 영향이 없다고 안내되어 있습니다. 챗봇 관리자센터 › 설정 › 챗봇 관리 › 카카오톡 채널 연결에서 이 채널을 개발 채널로 연결합니다. 연결하는 사람은 챗봇 마스터이면서 채널 매니저 이상이어야 합니다(A9 · B9 · B22).
6. **1:1 채팅 설정.** 파트너센터 채팅 설정에서 1:1 채팅을 켜고 채팅 가능한 요일 · 시간과 그 밖의 시간에 보일 안내 문구를 정합니다(B3). '상담직원 연결' 버튼은 운영 채널과 시험 채널 모두 1:1 채팅이 켜져 있어야 움직입니다(B12). 이 메뉴는 관리자 추가 인증이 필요합니다(B5).
7. **스킬 등록.** 인트라넷 '카카오톡 채널 연결' 카드에 나오는 주소와 확인 값을 스킬의 URL 과 '헤더값 입력' 칸에 붙여 넣습니다(B16).
8. **시험 채널에서 휴대폰으로 확인.** 글 보내기 · 사진만 보내기 · '상담직원 연결' · '수신 거부'라고 보내기를 해 봅니다. 인트라넷에 들어오는지 개발 담당과 같이 봅니다(7장 2번).
9. **문구 확정.** 인사 · 개인정보 수집 안내와 동의 · 접수 완료 · 못 알아들었을 때의 안내 문구를 대표가 승인합니다. 고치면 다시 승인합니다. 홍보 문구는 넣지 않습니다(5장).
10. **운영 채널 연결과 배포.** 운영 채널의 채팅방 메뉴를 끄고 5번과 같은 메뉴에서 운영 채널을 연결한 뒤, 마스터가 '배포'를 누릅니다. 운영 채널 연결은 봇을 한 번 배포해야 끝납니다(B9 · B10). 배포는 최대 30분 걸리고, 그동안 고칠 수 없고, 시작하면 멈출 수 없습니다(B10 · C8). 이때부터 실제 고객에게 챗봇이 답합니다.
11. **운영 채널에서 휴대폰으로 다시 확인.** 8번과 같은 항목을 봅니다. 시험에서는 되던 것이 운영 채널에서 안 됐다는 신고가 있습니다(G4).
12. **채널 주소 알리기.** 홈페이지 · 인스타그램 프로필에 채널 링크를 넣습니다(대표 승인 뒤).

### 5-2. 발송 규정

- **회사 규칙.** 승인 없는 고객 발송은 금지입니다. 챗봇의 고정 문구도 고객에게 가는 글이므로 배포 전에 대표가 승인합니다. 접수 뒤의 연락은 지금의 승인 흐름(메일)만 씁니다.
- **밤 시간 광고.** 오후 9시부터 다음 날 오전 8시까지 광고성 정보를 보내려면 받는 사람의 별도 사전 동의가 필요합니다(전자우편 제외). 어기면 3천만 원 이하 과태료 대상입니다(정보통신망법 제50조 제3항 · F1 · F2). 최신 조문은 원문 확인이 필요합니다.
- **카카오의 제한.** 채널 메시지는 20시 55분~다음 날 8시에 보낼 수 없습니다(B31). Event API 광고성 메시지는 오전 8시~오후 8시 50분에만 됩니다(A18). 광고성 메시지에는 '(광고)' 표시 · 수신거부 방법 · 고객센터 연락처가 꼭 들어가야 합니다(B33).
- **수신 동의.** 2026-03-04 에 올라온 안내서 개정본은 동의를 받을 때 '혜택 알림' · '정보제공' 같은 모호한 표현을 쓰지 못하게 했습니다. 동의는 2년마다 다시 확인해야 합니다(F3 · F4).
- **우리 구성에서의 뜻.** 이번 구성은 카카오로 먼저 보내는 것이 없어서, 위 제한의 대상이 되는 발송이 없습니다(이 문서의 해석입니다). 다만 접수 확인 문구에 홍보 내용을 넣으면 광고성 정보가 될 수 있으니 넣지 않습니다.

### 5-3. 개인정보 · AI

- 스킬 요청에는 고객을 알아볼 수 없는 구분 값만 옵니다. 연락처는 고객이 직접 입력해야 합니다(B17).
- 카카오톡 운영정책은 동의 없는 개인정보 수집을 금지합니다(E7). 연락처를 받기 전에 수집 목적 · 항목 · 보관 기간을 알리고 동의를 받습니다.
- 카카오비즈니스 약관은 이용자 데이터를 모으는 기술 · API 를 쓸 때 개인정보 위수탁 계약 또는 제3자 제공 동의 같은 절차를 지키라고 합니다(E6).
- 채널과의 1:1 대화는 카카오 서버에 3년 보관된다고 안내되어 있습니다(B3 · A21). 우리 쪽 보관 기간과 삭제 요청 처리는 따로 정해 개인정보처리방침에 적습니다. 지금 방침에는 인스타그램 항목만 있습니다(R11). 공개는 대표 승인 뒤에 합니다.
- 주민등록번호는 저장하지 않습니다(회사 규칙).
- AI 로 답하게 하면 그 사실을 미리 알리고 표시해야 합니다(AI 기본법 제31조 · 2026-01-22 시행으로 보도 · F5 · F6). 이번 구성은 정해 둔 문구만 쓰므로 해당하지 않습니다. 나중에 AI 응답을 붙이면 첫 인사에 밝혀야 합니다.

## 6. 위험과 한계

1. **5초 제한.** 우리 함수가 늦으면 답이 나가지 않습니다. 넘겼을 때 고객에게 무엇이 보이는지, 카카오가 다시 보내 주는지는 확인 못 함. 오류는 챗봇 관리자센터의 '스킬 오류 내역'(최대 100개)에서만 보입니다(B19).
2. **운영 채널에서 스킬이 불리지 않는 신고.** 2026년 포럼에 '봇테스트는 되는데 운영 채널 메시지가 1:1 채팅으로만 들어간다'는 글이 여럿 있고 원인 답변이 없습니다(G4 · G15). 사진만 보내면 스킬이 불리지 않는다는 글도 있습니다(G5). 그래서 개발보다 수신 시험을 먼저 합니다.
3. **사람 상담은 인트라넷에 보이지 않습니다.** 1:1 채팅으로 넘어간 뒤의 대화를 받는 무료 방법이 없습니다(G7). 미응대 경보는 '접수 건' 기준으로만 걸 수 있습니다.
4. **카카오톡으로 나중에 답할 수 없습니다(무료로는).** 접수 뒤의 답은 메일 · 전화 · 사람의 1:1 채팅입니다. 고객이 카카오톡 답을 기다리지 않도록 접수 완료 문구에 답하는 방법을 적어야 합니다.
5. **요청 확인이 약합니다.** 인스타그램 웹후크는 서명으로 확인하지만(R2) 카카오 스킬은 고정 값 비교뿐입니다. 3-4의 보완을 함께 넣습니다.
6. **기능이 서로 막습니다.** 챗봇을 붙이면 채널의 채팅방 메뉴 · 자동응답 메시지 · 카나나 상담매니저를 쓸 수 없습니다(A9 · B3).
7. **절차.** 비즈니스 채널 심사 대기, 배포는 마스터 한 사람 · 최대 30분(B10), 파트너센터 개편(2025-12-08)으로 예전 안내와 메뉴가 다를 수 있습니다(E5).
8. **일정.** 2단계(외부 협업방)가 11/19 에 시작합니다. 개발을 먼저 넣으면 그만큼 밀립니다.
9. **조사의 한계.** 카카오 페이지를 직접 열지 못했고 날짜를 대부분 확인하지 못했습니다. 아래 표의 항목은 카카오 화면에서 확인해야 합니다.
