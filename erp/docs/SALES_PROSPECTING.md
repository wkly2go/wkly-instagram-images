# 영업 대상 발굴·일정 기반 제안

`/sales` → **수주 파이프라인 → 신규 대상 발굴** → 조건 입력 → 검색/공식 확인 → 계획 적용 → 영업 정보 검수·저장.

## 개발 범위

- 팝업·신제품, 참가사, 출점·리뉴얼, 오피스 이전·리뉴얼, 매장·쇼룸 인테리어, 시즌, 공공·지원사업, 제휴, 재접촉의 9개 접근법. 대상 담당 부서·제안 방향·증거 목록·첫 질문을 제공한다.
- 브랜드·업종·지역·연월을 사용한 수요/공식공지/담당부서/참가사 검색. Google·네이버 새 창 링크로 조회하며 앱이 검색 결과를 수집하지 않는다. 연락처·내부 근거 메모는 검색문에 포함하지 않는다.
- 코엑스 공식 행사 일정, 기업마당, K-Startup, 기존 나라장터·거래처 화면을 연결한다. 출처 링크는 2026-11-13 확인. 검색 결과와 일정은 사용자가 공식 원문에서 확인해야 한다.
- 행사 시작/종료일·확인 상태·출처·확인일·근거를 기록한다. 확인 상태에는 시작일/출처/확인일/근거가 필수다. 역전 기간·잘못된 날짜·미래 확인일·URL 내 인증정보·위험 URL을 거부한다.
- 준비 기간 7~180일로 제안 일정을 역산한다. 기본 21~120일은 업무 제안값이며 시장 사실/마감 보장이 아니다. 공공사업 질의·입찰 마감은 별도 확인한다.
- 검토 준비도는 출처 근거 25, 일정 확인 20, 문의 창구 15, 수요 25, 미래 일정 15점의 입력 충실도다. 수주 확률이나 AI 평가가 아니다.
- 적용하면 기존 영업 제목·회사·출처·다음 행동·연락일·요청 메모에 계획을 채운다. 확인된 미래 행사만 미래 첫 연락일을 사용하고, 미확인·경과·종료 행사는 오늘 확인/후속 업무를 제안한다.
- 기존 금액·담당자 등은 보존하며 같은 회사의 연결은 유지한다. 수행 회사 변경 시 거래처/담당자/프로젝트 연결을 해제한다. 적용 시 기존 입력 변경은 확인한다.
- 변경된 발굴 계획을 적용하지 않으면 저장을 차단한다. 미저장 이동 보호와 기존 동일 ID/revision·운영 역할 권한을 유지한다. 검색·계획 적용만으로 쓰기 요청하지 않는다.

## 저장 범위

새 DB 구조 없이 기존 영업 기회에 저장한다. 전체 계획은 사람이 읽을 수 있는 요청 메모, 첫 후속 날짜는 기존 `next_date`다. 상세에서 메모와 날짜를 함께 수정한다. 계획 항목별 독립 캘린더 레코드, 외부 일정 변경 감시, 담당자 자동 수집, 자동 영업 메시지 발송은 이번 범위가 아니다. 기존 미완료 외부 연동을 완료로 표시하지 않는다.

## 이전 발굴 계획 기능의 검증 이력

순수 로직은 `tests/prospecting.test.ts`, 실제 React 입력·적용·저장·권한·미저장 보호는 `tests/ui/growth-dom.test.mjs`에 추가했다. 전체 기능·로컬 DB 검사 331/331, React DOM 31/31 (총 362/362), TypeScript·프로덕션 빌드를 통과했다. 매뉴얼 anchor 9개·이미지 6개 경로가 정상이며 기존 큰 번들 경고는 남아 있다. 체험/모의 API 검증은 운영 RLS·실계정·실제 브라우저/모바일 화면 검증을 대신하지 않는다. 새 화면 캡처는 별도 확인 대상이며 기존 매뉴얼의 화면은 이전 체험판 캡처다.

사용설명: `public/manual/growth.html#prospecting`. 외부 유료 API·SQL 재실행·Edge 배포·예약 생성·메일/DM·게시·광고 집행 없음.


## 조사 결과에서 수주 실행까지

발굴 계획의 검색 링크는 사람이 조사할 항목을 정리하는 보조 기능이다. 앱이 외부 웹에서 영업 대상을 자동 발굴·등록하는 기능은 아직 없다. 이미 조사한 결과는 **민간 영업 후보 / 나라장터 공고 → 발굴 보고서 가져오기**로 연결한다.

1. JSON 파일 또는 원문을 미리보기하고 출처·확인일·수요·제안 방향·기존 접촉 여부를 검수한다.
2. 원하는 후보를 체크해 **선택한 후보 검토함에 저장**한다. `검토` 상태로 등록하며 영업 대상 확정·연락·입찰을 실행하지 않는다.
3. 성공 후보는 제외하고 실패 후보는 같은 ID·내용으로 다시 확인한다. 상태는 열린 창에서만 유지하며 새로고침 후 복구는 제공하지 않는다. 한 건을 편집기로 넘기면 나머지 후보와 원문은 닫히므로 원본 보고서를 보관한다.
4. 개별 후보의 조건을 검토해 영업 기회로 연결한다. 다음 행동과 연락일은 영업 상세에서 지정한다.
5. 콘텐츠·광고 / 공간·인테리어 / 나라장터·공공 입찰의 단계별 실행 안내로 할 일과 근거를 확인한다. **다음 행동 예시 적용**은 행동 텍스트만 바꾸며 단계·날짜·계약을 자동 확정하지 않는다.
6. 수주 근거와 최종 수행 자료를 확인하고 같은 회사·거래처의 프로젝트로 인계한다. 새 프로젝트는 별도 창의 기존 등록 절차로 만들고, 영업 편집기에서 목록을 새로고침해 선택·저장한다.

나라장터는 공식 원문·정정 여부와 업종·지역·실적·직접생산 자격을 대조한다. 방문 제안서와 전자 가격입찰 마감이 다를 수 있어 가장 이른 필수 마감과 각각의 제출 방식을 따로 적는다. 낙찰·우선협상 통보와 계약 체결을 구분한다.

현재 코드/운영 경계와 상세 사용 순서는 [SALES_DISCOVERY_20261113.md](SALES_DISCOVERY_20261113.md), [사용설명](../public/manual/growth.html#discovery)을 따른다. `g2b-search` 배포는 완료 기록이 있으나 키·활용 승인·실응답은 별도 확인이다. Gmail의 실제 후보 생성, Instagram의 신규 DB/Edge·Meta 권한·실계정 수집 역시 운영 검증이 필요하다. 이 후속 절은 새 테스트·배포 완료를 의미하지 않는다.
