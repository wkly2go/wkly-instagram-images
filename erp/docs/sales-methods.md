# 영업 내용 검증과 실행 방법

대상 사업은 팝업스토어 대행 수주다. 기획·공간 제작·운영·홍보 중 실제 수행 가능한 범위를 제안한다. 견적, 수행 실적, 성과 수치, 고객사 이름은 검증된 자료 없이 만들지 않는다.

## 화면 사용 순서

1. 리스트에서 회사·사람, 예상 영업 내용과 원문 단서를 함께 읽는다.
2. **내용 검증**을 열어 저장된 원문 기록과 출처를 대조한다. 수집 기록이 제목·메모뿐이면 원문 전체를 열어 확인한다.
3. 발주처·협력사·소개 제휴 역할과 실제 수요, 수행 범위, 확인 근거를 기록한다. 모르는 내용은 추측해서 채우지 않는다.
4. 관리자가 검증 결과를 저장한다. 추가 확인·보류·제외 상태에서는 새로운 파이프라인을 만들지 않는다.
5. 확인한 내용으로 영업을 시작한다. 기존 연결 건은 그대로 열리며 중복 생성하지 않는다.
6. 후보 원문·소속·연락처·행사 날짜가 바뀌면 신규 연결 전에 재검증한다. 단순 취합 시각 변경만으로는 기존 검증을 지우지 않는다.

## 상황별 방법

| 상황 | 접근 | 다음 단계 조건 |
|---|---|---|
| 기존 문의 | 기존 스레드에서 현재 추진 여부와 미발주 범위를 확인하고 1쪽 답변 준비 | 실제 수요와 제안 검토 일정 확인 |
| 브랜드 | 공식 출시·매장·팝업 단서에 맞춰 담당 부서에 작은 제안 가설의 검토 의향 확인 | 목표·일정·미발주 업무 확인 |
| 협력사 | 공급 제안과 직접 발주를 구분하고 실제 공동 고객 건·역할·정산 방식 확인 | 구체적인 고객 건과 공동 수행 범위 확인 |
| 공간 운영사 | 가능 일정·대관 조건·브랜드 유치 역할을 확인하고 운영안 제안 | 비용 부담 주체와 수행 역할 확인 |
| 입찰 | 공식 공고·정정·과업·참가 자격·평가 기준을 대조하고 참여 결정 | 자격과 증빙, 제출 담당·일정 확정 |
| 공개 행사 | 공식 주최기관의 미발주 과업이나 협업 모집을 조사 | 행사 안내와 별개인 실제 발주·협업 근거 확인 |

회사명·연락처·관련 키워드는 발주 의사가 아니다. 공개 행사 목록은 입찰 공고가 아니다. 공급업체 홍보를 구매 문의로 확정하지 않는다. 자동 분류와 영업 방법은 규칙 기반 제안이며, 문안은 검토용 초안이다. 자동 발송 기능은 없다.

## 검토한 스킬과 적용 범위

검토일: 2026-11-14. 설치된 마케팅 스킬, OpenAI 공식 설치 가능 목록, 공개 Marketing Skills 카탈로그를 검색하고 아래 원문을 검토했다. 관련 원칙을 앱의 규칙·문안·검증 단계에 적용했으며 모델 자체를 재학습한 것은 아니다.

- [prospecting](https://github.com/coreyhaines31/marketingskills/tree/main/skills/prospecting) v1.5.3: 대상 적합성·지금 접근할 이유·근거를 분리한다. 출처와 담당 역할을 확인한다.
- [sales-enablement](https://github.com/coreyhaines31/marketingskills/tree/main/skills/sales-enablement) v2.4.3: 상황별 질문, 1쪽 제안, 증거, 반론 대응을 준비한다. 임의의 실적을 쓰지 않는다.
- [cold-email](https://github.com/coreyhaines31/marketingskills/tree/main/skills/cold-email) v2.2.4: 실제 맥락에 맞춘 짧은 연락, 구체적인 질문, 작게 시작하는 다음 행동을 사용한다.
- [revops](https://github.com/coreyhaines31/marketingskills/tree/main/skills/revops) v2.2.4: 단계별 완료 조건·담당자·다음 연락일을 명시하고 실제 결과를 기록한다.

SaaS의 일반적인 전환율·매출 수치는 이 사업의 근거로 사용하지 않는다. 유료 자료 구매, 무단 수집, 외부 연락 발송은 적용 범위에 포함하지 않는다. 위 자료의 실행 지시는 사용자 승인 범위를 넓히지 않는다.
