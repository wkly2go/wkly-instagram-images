# 회의록 서버 함수 배포 준비

2026-11-12 기준. 대상 프로젝트는 `hophgcpszenrvchvbkav`, 함수 이름은 **`meeting-minutes`**입니다. 이 문서는 단일 파일 배포물의 준비·로컬 검증 기록입니다. **이번 작업에서 Supabase 함수 배포나 운영 호출은 실행하지 않았습니다.** 웹 main 병합과 Cloudflare 배포는 이 함수의 배포를 대신하지 않습니다.

현재 함수는 외부에서 받아쓴 텍스트로 Claude 회의록 초안을 만듭니다. 음성 직접 받아쓰기는 지원하지 않으며, Claude API 사용은 별도 과금입니다. 이번 변경은 원본 두 파일을 대시보드용으로 합치고 화면 안내를 정정하며 서버 처리 로직·보관 정책·예산은 바꾸지 않습니다.

## 1. 배포물 생성과 검사

저장소의 `erp` 디렉터리에서 실행합니다.

```sh
npm run build:meeting-dashboard
node scripts/build-meeting-minutes-dashboard.mjs --check
npm run test:meeting
```

- 원본: `supabase/functions/meeting-minutes/cleanup.ts`, `index.ts`
- 생성 파일: [`supabase/deploy/meeting-minutes-dashboard.ts`](../supabase/deploy/meeting-minutes-dashboard.ts)
- 생성기는 두 원본과 SHA-256을 기록하며 내부 `./cleanup.ts` import만 제거합니다. 고정 버전 npm import는 유지합니다.
- 원본을 고치면 다시 생성합니다. 생성 파일만 직접 수정하지 않습니다. `--check`가 실패하면 배포하지 않습니다.
- 배포물 검사 10개와 기존 정리 검사 8개는 모의 SDK·저장소에서 실행합니다. 운영 DB·Storage·Claude를 호출하지 않습니다. 구문·동작 검사이며 Supabase 런타임의 배포 성공을 증명하지 않습니다.

## 2. 실제 배포 시 확인할 사항

1. Supabase에서 프로젝트 ID와 기존 **meeting-minutes** 함수를 확인하고 현재 배포 버전을 기록합니다. 다른 함수의 코드를 교체하지 않습니다.
2. 편집기의 `index.ts`에 생성 파일 **전체**를 넣습니다. 원본 `index.ts`만 붙이면 `cleanup.ts` 의존성이 빠집니다. 기존 편집 파일과 다른 변경이 있는지 먼저 비교합니다.
3. JWT 검증을 유지합니다. 시험 편의를 위해 인증을 끄거나 공개 함수로 바꾸지 않습니다.
4. `ANTHROPIC_API_KEY` 설정은 존재 여부만 확인합니다. Supabase 기본 URL·anon·service role 환경값과 기존 키를 유지하며 값을 채팅·문서·소스·스크린샷에 넣지 않습니다.
5. 배포 결과에서 함수 이름·성공 상태·배포 시점을 기록합니다. 코드 생성이나 웹 배포만 끝난 경우에는 **서버 배포 대기**로 표시합니다.

이 준비 작업에는 DB 설치가 필요하지 않습니다. **0107 및 이미 성공한 0113·0114·0115를 재실행하지 않습니다.** 회의록의 기존 SQL도 이력 누락만으로 재실행하거나 전체 `db push`를 하지 않습니다. 기존 `meeting_recordings`, 비공개 `meeting-audio`, 권한·정책 상태 확인과 새 설치는 별개입니다.

## 3. 비용·데이터 변경 없는 확인 범위

아래는 함수 본문에 도달했을 때의 응답입니다. 플랫폼 JWT 검증이 먼저 차단하면 해당 응답만 확인될 수 있으며, 이를 피하려고 인증 설정을 바꾸지 않습니다.

| 요청 | 함수 응답 | 검증 범위 |
|---|---|---|
| OPTIONS | 200 | 사전 요청 응답 |
| GET | 405 | 지원하지 않는 메서드 거부 |
| Authorization 없는 POST `{}` | 401 | 로그인 없는 요청 거부 |

이 경로가 로컬 배포물 테스트에서 AI 호출·Storage 작업·DB 쓰기·백그라운드 처리를 시작하지 않는지 검사합니다. 잘못된 세션·JSON·ID, 조회되지 않는 기록, 이미 처리 중인 기록도 모의 환경에서 검사합니다. 인증이 필요한 시험을 위해 토큰이나 키를 채팅에 전달하지 않습니다.

**운영에서 실제 기록 ID를 넣어 시험하거나 회의록 작성 버튼을 누르지 않습니다.** 정상 처리 경로는 Claude 비용을 발생시킬 수 있고, 처리 후 정리가 30일 지난 원본을 영구 삭제할 수 있습니다. 생성이 실패하더라도 정리가 이어질 수 있습니다. 실제 생성·정리 시험은 비용 한도와 보관 대상이 확인된 별도 작업입니다.

## 4. 남은 운영 검증과 기존 제한

- **별도 예산 경로:** meeting-minutes는 growth-ai의 기간 한도·사용 기록과 연결되어 있지 않습니다. 인트라넷 AI 사용 화면의 한도를 이 함수의 한도라고 해석하지 않습니다.
- **동시 요청:** 처리 중 여부 확인과 상태 변경이 원자적이지 않아 동시에 시작한 요청의 중복 호출 방지는 별도 보완 대상입니다. 이미 처리 중인 행을 읽은 요청의 재실행 방지 테스트가 이 경쟁 조건까지 검증하지는 않습니다.
- **결과 저장:** 최종 DB 갱신 오류를 확인하지 않는 기존 경로가 있어 AI 응답 뒤 저장에 실패하면 처리 중 상태가 남을 수 있습니다. 운영 기록과 오류 처리를 별도로 점검합니다.
- **원본 정리:** 새 회의 처리 뒤 최대 50건을 확인합니다. 정기 예약 작업이 아니므로 정확히 30일에 지워지거나 배포 직후 용량이 줄어든다고 보장하지 않습니다. 공유 참조·처리 중 파일 보호와 실패 시 참조 보존은 기존 정리 테스트 범위입니다.
- **실제 사용:** 로그인한 관리자·작성자의 텍스트 업로드, 권한, 완료 결과 저장, 처리 실패 경로는 운영 검증 전입니다. 모델 사용 가능 여부·실제 잔액·조직 전체 비용도 별도 확인이 필요합니다.

Supabase Usage·Storage·Egress 수치는 아직 확인 전입니다. 기존 읽기 전용 용량 점검은 [`SUPABASE_CAPACITY_OPTIMIZATION.md`](SUPABASE_CAPACITY_OPTIMIZATION.md)를 따르며, 배포 준비나 로컬 테스트 통과를 비용 절감·사용량 경고 해제로 보고하지 않습니다.
